# Contributing to Spec Composer

Thanks for your interest in improving Spec Composer. Bug reports, feature ideas,
documentation fixes and code contributions are all welcome.

## Ways to contribute

- **Report a bug**: open an issue with steps to reproduce, what you expected
  and what happened.
- **Suggest a feature**: open an issue and describe the problem you want
  solved, not only the solution.
- **Improve the docs**: typo fixes and clearer explanations are always useful.
- **Send a pull request**: see below. For anything larger than a small fix,
  please open an issue first so we can agree on the approach before you invest
  time.

Security problems are the exception: do **not** open a public issue. Follow
[SECURITY.md](SECURITY.md).

## Development setup

You need [Node.js](https://nodejs.org) 22.12 or newer. Use npm and the
committed `package-lock.json`; a clean install with `npm ci` is verified.

Clone your fork using its GitHub URL, then run from the project directory:

```sh
npm ci
npm run dev
```

Useful scripts:

| Command                | Purpose                                |
| ---------------------- | -------------------------------------- |
| `npm ci`               | Reproducible install from the lockfile |
| `npm run dev`          | Development server                     |
| `npm run typecheck`    | TypeScript check                       |
| `npm run build`        | Production build                       |
| `npm run lint`         | ESLint                                 |
| `npm run format`       | Prettier (rewrites files)              |
| `npm run format:check` | Check formatting (no rewrite)          |

## Pull request workflow

1. Fork the repository and create a branch from `main`:
   `git switch -c fix/short-description`.
2. Make your change. Keep the pull request focused on one thing; unrelated
   clean-ups belong in a separate PR.
3. Run `npm run typecheck`, `npm run build` and `npm run lint`. There is no
   automated test suite yet, so also verify the change manually (next step).
4. Try the change in the browser, including the editor flows it touches.
5. Open the pull request against `main` and describe what changed and why.
   Link the issue it addresses, and add screenshots or a short recording for
   UI changes.

A maintainer will review it. Expect some back-and-forth; requests for changes
are normal and not a rejection.

## Commit messages

Use short, imperative messages, ideally following
[Conventional Commits](https://www.conventionalcommits.org):

```text
feat: add LinkedIn banner format
fix: keep snapping guides visible while zooming
docs: explain brand kit storage
```

## Code guidelines

- **TypeScript**: keep types strict and avoid `any`. The document shape lives in
  `src/features/spec-composer/types.ts`; if you change it, update the schema,
  the templates that depend on it and the compiler together.
- **Formatting**: Prettier and ESLint are the source of truth. Do not hand-format
  around them.
- **Components**: follow the existing patterns. UI primitives are shadcn/ui
  components in `src/components/ui`; prefer composing them over adding new UI
  libraries.
- **Dependencies**: think twice before adding one. Explain why it is needed in
  the pull request, and confirm its license is compatible with MIT.
- **Generated files**: do not edit `src/routeTree.gen.ts` by hand; it is
  regenerated by the router plugin.
- **Determinism**: the prompt compiler is meant to be deterministic and free of
  network calls. Keep it that way.

## Licensing of contributions

Spec Composer is released under the [MIT License](LICENSE). By submitting a
contribution you confirm that you have the right to submit it and agree that it
will be licensed under the same terms. Do not include code, fonts or images
whose license does not allow this.

### Images and other assets

- Only add images you created yourself, including with AI tools whose terms
  allow this use, or images under a license compatible with MIT.
- Record every new image, logo or font in [ATTRIBUTIONS.md](ATTRIBUTIONS.md):
  its path, whether it is AI-generated and, for third-party material, its
  source and license.
- Do not add images of real, identifiable people. Add third-party logos only to
  identify a tool, from an official source, and note the source in
  `src/features/spec-composer/tool-logos.ts` and ATTRIBUTIONS.md.
